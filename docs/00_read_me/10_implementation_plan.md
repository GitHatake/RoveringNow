## Phase 1：詳細設計

**ブランチ：`docs/detailed-design`**

基本設計書が「何を作るか」を定義したのに対し、本フェーズでは「どう作るか」を定義する。

- [ ] 技術スタックの選定
  - [ ] **提供形態の最終判断**（WEBアプリのままか、ネイティブアプリ化するか）
  - [ ] フロントエンド／バックエンド／データベース／インフラ
  - [ ] プッシュ通知の実現方式
- [ ] データベース設計（論理・物理）
- [ ] API仕様
- [ ] 画面詳細設計・UIデザイン
- [ ] 認証・認可の方式
- [ ] **QR不正取得への対策方式**（動的QR・有効期限等）
- [ ] **ローバーポートからの新着検知方式**の調査（Phase 2向け）
- [ ] 監査ログの保持期間（匿名性ポリシーの実装方針）

### 特に判断が重い項目

**提供形態の最終判断。** 基本設計書 第14.2節の制約1のとおり、WEBアプリでは iOS でホーム画面に追加されない限りプッシュ通知が届かない。通知が生命線である本アプリにとって、この制約を受け入れるかどうかは全体の技術選定を左右する。

## Phase 2：実装（MVP）

MVPは機能1・2・3の3機能に及ぶため、実装内部でも順序を固定する。

| # | ブランチ | 内容 |
|---|---|---|
| 2-1 | `feat/foundation` | 認証・組織管理・通知基盤 |
| 2-2 | `feat/timeline` | 連絡機能（F-04〜F-07） |
| 2-3 | — | **協力組織による中間検証** |
| 2-4 | `feat/stamp` | スタンプ機能（F-08・F-09）＋QR基盤 |
| 2-5 | `feat/card` | カード交換機能（F-10・F-11）＋コレクション（F-12） |
| 2-6 | `feat/report` | 通報機能（F-14） |

### 2-1 基盤

- [ ] 会員登録・認証（F-01）
- [ ] 組織の検索・所属申請（F-02）
- [ ] 組織管理・メンバー承認（F-03）
- [ ] 組織ツリーと配信範囲の導出ロジック
- [ ] 通知基盤・通知チャンネル設定（F-13）
- [ ] オンボーディング（ホーム画面追加案内・通知許諾）

### 2-2 連絡機能

- [ ] 連絡の投稿・配信範囲選択（F-04）
- [ ] 統合タイムライン・組織フィルタ（F-05）
- [ ] コメント（F-06）
- [ ] リアクション（F-07）

### 2-3 中間検証（必須）

- [ ] 協力組織に実際に触ってもらう
- [ ] 指摘を 2-4 以降の実装と設計書に反映する

> ウォーターフォールではリリース前に価値を検証する機会がない。連絡機能が動いた時点で一度実物に触ってもらうこの工程は、**省略しない**。

### 2-4 スタンプ機能

- [ ] 不正取得への対策
- [ ] 運営者による獲得取消

### 2-5 カード交換機能

- [ ] プロフィールカード編集（F-10）
- [ ] カード交換・つながりの成立（F-11）

### 2-6 通報機能

## 意思決定テーブル

基本設計フェーズで確定した判断。詳細と理由は[基本設計書 第15章](../10_source/01_basic_design.md#15-意思決定履歴)を参照。

| # | 項目 | 決定 | 日付 |
|---|---|---|---|
| 1 | MVPスコープ | 機能1（連絡）＋2（スタンプ）＋3（カード交換） | 2026-08-16 |
| 2 | 参加方法 | 誰でも登録可、組織への所属のみ管理者承認 | 2026-08-16 |
| 3 | 無所属ユーザーの権限 | 制限なし（カードに「所属未確認」表示のみ） | 2026-08-16 |
| 4 | 連絡の見え方 | 統合タイムライン＋組織フィルタ | 2026-08-16 |
| 5 | 投稿権限 | 投稿は組織管理者のみ／コメントは全メンバー可 | 2026-08-16 |
| 6 | 既読管理 | 実装せず、リアクションで代替 | 2026-08-16 |
| 7 | 組織モデル | 親組織IDを1つ持つツリー構造＋配信範囲の選択 | 2026-08-16 |
| 8 | スタンプ付与 | 会場QRを参加者がスキャンして自動付与 | 2026-08-16 |
| 9 | スタンプのデザイン | テンプレート生成主体＋画像アップロードも許可 | 2026-08-16 |
| 10 | カードの情報 | 表示名・所属・自己紹介・アバター＋SNSリンク等を任意で | 2026-08-16 |
| 11 | つながりの定義 | カード交換＝つながり。Phase 3のDM解禁条件 | 2026-08-16 |
| 12 | 匿名性ポリシー | 仮名性（UI上は匿名／内部的に追跡可能） | 2026-08-16 |
| 13 | ローバーポート通知 | 新着時に全登録者へ即時プッシュ | 2026-08-16 |
| 14 | 通知チャンネル | 種別ごとに独立してON/OFF可能 | 2026-08-16 |
| 15 | 通報機能 | MVPに含める | 2026-08-16 |
| 16 | カード交換の成立条件 | 片方がスキャンすれば双方向に成立 | 2026-08-16 |
| 17 | 組織の登録主体 | システム管理者が登録・初代管理者を任命 | 2026-08-16 |
| 18 | QRスキャナの配置 | ナビゲーション中央に単一のスキャナ、種別は自動判別 | 2026-08-16 |
