# RoveringNow — プロジェクト概要

**最終更新日：2026-08-16**

## これは何か

日本のボーイスカウト運動における「ローバースカウト」部門（18〜26歳）を対象とした、SNS型のWEBアプリケーション。

> ### 連絡が届き、活動が記録され、仲間が集まる
> **— ローバースカウトのためのデジタル手帳**

## 解決する課題

| # | 課題 | 対応 |
|---|---|---|
| 1 | 所属組織からメンバーへの**情報伝達が機能していない** | 統合タイムラインとグループツリーによる配信 |
| 2 | 活動への**参加意欲が年々低下**している | 活動スタンプによる記録の蓄積 |
| 3 | ローバースカウト**同士の交流**が乏しい | QRによるプロフィールカード交換 |
| 4 | 全国ブログ「ローバーポート」の**アクティブユーザーが少ない** | 新着記事のプッシュ配信 |

課題は独立していない。**課題1が解決しなければ課題2〜4も解決しない**。情報が届かない状態では、活動への参加自体が起こらず、交流も生まれず、記事も読まれないためである。したがって本アプリは情報伝達を土台とし、その上に参加動機づけと横のつながりを積み上げる構造をとる。

## 中心概念：グループ

本アプリにおける連絡の発信主体は「**グループ**」であり、**誰でも作成できる**。

| 種別 | 例 | 性質 |
|---|---|---|
| 公式組織 | ○○団ローバー隊、△△地区ローバー会 | 恒久的。認証バッジの対象 |
| プロジェクト | 全国大会実行委員会 | 期限付き |
| イベント | 夏季合同キャンプ2027 | 期限付き |
| その他 | 有志の集まり、勉強会 | 自由 |

ローバースカウトの活動は、恒久組織だけでなく**プロジェクトやイベントごとの一時的な集まり**によって動いている。恒久組織のみを対象とすると、こうした集まりはアプリの外（メッセージアプリのグループ等）で運用され、連絡が再び分散する。すべてを同じ「グループ」として扱うことで、あらゆる連絡が単一のタイムラインに集約される。

グループは親子関係を持てるため、地区が配信した連絡が配下の各団メンバー全員へ自動的に届く。**課題1はこの構造によって解決される。**

## 開発方針

**ウォーターフォール式**で進行する。

```
基本設計  →  詳細設計  →  実装  →  テスト
  ✅完了      次フェーズ
```

**設計書が開発をハンドリングする。** 設計書と実装が食い違った場合は設計書を正とし、実装都合で仕様を変える必要が生じた際は、実装より先に設計書を改訂して理由を記録する。

各フェーズの責務は次のとおり厳密に分離する。

| フェーズ | 決めること | 決めないこと |
|---|---|---|
| **基本設計** | 何を作るか（機能・体験・データの概念・運用ルール） | 技術的な実現方式 |
| **詳細設計** | どう作るか（技術スタック・API・テーブル定義・画面詳細） | — |

## リリース計画

| フェーズ | 含む機能 |
|---|---|
| **MVP（Phase 1）** | グループ・連絡・活動スタンプ・カード交換・通知基盤・通報 |
| **Phase 2** | ローバーポート新着配信・匿名掲示板 |
| **Phase 3** | ダイレクトメッセージ（実名／匿名） |

**ローンチは全国一斉導入**とする。ただし全国公開の前に、協力グループによる**クローズドβ**を実施する。ウォーターフォールではリリース前に実ユーザーの反応を見る機会が構造的に存在せず、かつ全国一斉では問題があった場合に全国のユーザーが同時にそれを踏むため、この工程は省略しない。
