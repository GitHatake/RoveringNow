# RoveringNow — プロジェクト概要

**最終更新日：2026-08-17**

## これは何か

日本のボーイスカウト運動における「ローバースカウト」世代を対象とした、SNS型のWEBアプリケーション。

対象年齢は**18〜26歳**とする。日本連盟によるローバースカウト部門の公式区分は「18歳以上25歳以下」だが、登録を離れた直後の層こそ参加意欲の低下が顕在化するため、意図的に1歳分を広げている。

> ### 連絡が届き、活動が記録され、仲間が集まる
> **— ローバースカウトのためのデジタル手帳**

## 解決する課題

| # | 課題 | 対応 |
|---|---|---|
| 1 | 所属組織からメンバーへの**情報伝達が機能していない** | 統合タイムラインとグループツリーによる配信 |
| 2 | 活動への**参加意欲が年々低下**している | 参加意向の可視化と、活動スタンプによる記録の蓄積 |
| 3 | ローバースカウト**同士の交流**が乏しい | QRによるプロフィールカード交換 |
| 4 | 全国ブログ「ROVERPORT」の**アクティブユーザーが少ない** | 新着記事のプッシュ配信 |
| 5 | 所属を越えて**知らないスカウトと話せる場がない** | 匿名掲示板とDM |

課題は独立していない。**課題1が解決しなければ他の課題も解決しない**。情報が届かない状態では、活動への参加自体が起こらず、交流も生まれず、記事も読まれないためである。したがって本アプリは情報伝達を土台とし、その上に参加動機づけと横のつながりを積み上げる構造をとる。

ただし、**情報が届くことと人が動くことは別**である。連絡が届いても参加につながらなければ課題2は解決しない。そのため、参加した「後」に報いるスタンプに加えて、参加する「前」に働く仕掛け（「参加したい」の可視化）を設けている。

## 中心概念：グループ

本アプリにおける連絡の発信主体は「**グループ**」であり、**誰でも作成できる**。

| 種別 | 例 | 性質 |
|---|---|---|
| 公式組織 | ○○団ローバー隊、△△地区ローバー会 | 恒久的。認証バッジの対象 |
| プロジェクト | 全国大会実行委員会 | 期限付き |
| イベント | 夏季合同キャンプ2027 | 期限付き |
| その他 | 有志の集まり、勉強会 | 自由 |

ローバースカウトの活動は、恒久組織だけでなく**プロジェクトやイベントごとの一時的な集まり**によって動いている。恒久組織のみを対象とすると、こうした集まりはアプリの外（メッセージアプリのグループ等）で運用され、連絡が再び分散する。すべてを同じ「グループ」として扱うことで、あらゆる連絡が単一のタイムラインに集約される。

グループは親子関係を持てるため、地区が配信した連絡が配下の各団メンバー全員へ自動的に届く。**課題1はこの構造によって解決される。**

## 開発方針

**ウォーターフォール式**で進行する。

```
工程0        工程1      工程2   工程3    工程4        工程5
基本設計  →  詳細設計  →  実装  →  テスト  →  β  →  全国公開
 レビュー中
```

> **呼称の区別：** 上記の「工程0〜5」は開発の工程を指す。これとは別に「Phase 1〜3」という呼称があり、こちらは**機能の提供段階**（MVP／ローバーポート・掲示板／DM）を指す。両者は対応しない。

**設計書が開発をハンドリングする。** 設計書と実装が食い違った場合は設計書を正とし、実装都合で仕様を変える必要が生じた際は、実装より先に設計書を改訂して理由を記録する。

各フェーズの責務は次のとおり厳密に分離する。

| 工程 | 決めること | 決めないこと |
|---|---|---|
| **基本設計** | 何を作るか（機能・体験・データの概念・運用ルール・**プロダクト形態**） | 技術的な実現方式 |
| **詳細設計** | どう作るか（技術スタック・API・テーブル定義・画面詳細） | 基本設計で確定した事項の変更 |

提供形態（WEBアプリ／PWA）は**プロダクト形態の判断**であるため、技術選定ではなく基本設計で確定している。詳細設計でこれを覆すことはしない。

## リリース計画

| 機能段階 | 含む機能 |
|---|---|
| **Phase 1（MVP）** | グループ・連絡・活動スタンプ・カード交換・関係の解消・管理者の交代・通知基盤・通報 |
| **Phase 2** | ROVERPORT 新着配信・匿名掲示板 |
| **Phase 3** | ダイレクトメッセージ（実名／匿名） |

**ローンチは全国一斉導入**とする。ただし全国公開の前に、協力グループによる**クローズドβ**を実施する。ウォーターフォールではリリース前に実ユーザーの反応を見る機会が構造的に存在せず、かつ全国一斉では問題があった場合に全国のユーザーが同時にそれを踏むため、この工程は省略しない。

### プロジェクトの位置づけ

本プロジェクトは**同人制作（有志による自主開発）**として進行する。正式な承認と運営の責任主体（個人情報取扱事業者・規約制定者）の確定は、**アプリケーションの完成後に稟議へ諮る**。

ただし、**実在の利用者を迎える前には責任主体が確定していなければならない**。個人情報を収集する以上、取扱事業者が不在のまま実運用に入ることはできないため、クローズドβより前に稟議を通す必要がある。

設計はこれに備え、特定の運営体制に依存しない形をとる。運営作業の担当者は人数や所属で固定せず、権限（システム管理者ロール）として抽象化している。

### データの保持方針

**原則として無期限に保持する。** 活動の記録が蓄積されることが本アプリの価値であり、1人の退会でグループの連絡履歴が虫食いになることは避ける。

ただし**退会時には個人を特定する情報のみを削除する**（氏名・メールアドレス・アバター・プロフィールカード）。投稿・コメント・監査ログといった記録は残り、投稿者は「退会したユーザー」として表示される。記録は残しつつ、退会者の個人データは保持しない形である。

### 未決事項

**詳細設計の開始をブロックする項目はない。** 10件の未決事項は基本設計書 第14.4節に一覧化しており、工程1以降で順次確定する。

### 外部との合意が必要な事項

本設計には、アプリ運営の一存では成立しない事項が含まれる（基本設計書 第12.6節）。

| 相手 | 事項 | 時期 |
|---|---|---|
| 日本連盟／県連盟等 | 公式組織の認証と名称移管の正当性 | 全国公開前 |
| RCJ（全国ローバースカウト会議） | ROVERPORT の記事取得・利用許諾 | Phase 2 着手前 |
| 協力グループ | クローズドβへの参加 | テスト完了後 |
| 法務専門家 | インターネット異性紹介事業への該当性 | Phase 3 着手前 |
