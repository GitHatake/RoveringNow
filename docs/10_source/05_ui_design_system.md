### 本書の位置づけ

画面ごとの仕様ではなく、**すべての画面が共有する語彙**を定める。色・文字・間隔・部品・動きの決まりごとを1か所に集約し、画面詳細設計（`06_screen_spec.md`）はここで定義した部品を組み合わせて記述する。

デザインの方向性は基本設計フェーズで確定している。

> **ミニマル基調＋コレクションにのみ質感**

## 1. デザイン原則

### 1.1 二層構造

このアプリは、性格の異なる2つの領域を持つ。**同じ見た目にしてはならない。**

| 領域 | 該当画面 | 性格 | 表現 |
|---|---|---|---|
| **実用の層** | タイムライン、連絡詳細、グループ、設定、管理 | 読む・判断する・操作する | 無彩色を基調に、余白で構造を示す。装飾を持たない |
| **愛着の層** | コレクション（スタンプ・カード） | 眺める・集める・振り返る | 紙の地と箔押し風の縁。集めたものが「もの」として見える |

**実用の層は読みやすさに徹し、愛着の層にのみ質感を差す。** 全面を質感で覆うと連絡が読みにくくなり、全面をフラットにするとコレクションが「ただのリスト」になる。この使い分け自体が、アプリの人格になる。

### 1.2 5つの原則

| # | 原則 | 意味 |
|---|---|---|
| 1 | **色は語らない、余白が語る** | 情報の階層は、色数ではなく余白と文字の大きさで示す。使う色は無彩色と深緑1色だけ |
| 2 | **1画面に主行動は1つ** | 主要なボタンは画面に1つだけ。複数あるなら、その画面は2つの仕事をしている |
| 3 | **既定値で完成している** | 設定しなくても使える。設定は「変えたい人が変える」ためにある |
| 4 | **状態を隠さない** | 読み込み中・空・失敗のそれぞれに固有の表示を持つ。何も出さない時間を作らない |
| 5 | **人を追い詰めない** | 未達成・未設定・未所属を、赤や警告として示さない（基本設計書 プロダクト原則7） |

原則5は、基本設計で「所属未確認」表示を廃止した判断（決定38）と同じ考え方である。**状態の可視化が本人の不利益に働いてはならない。**

## 2. カラー

### 2.1 考え方

**無彩色＋深緑1色。** アクセント色を1つに絞ることで、色が意味を持つ。深緑が現れる場所は「押せる」「今ここ」「達成した」のいずれかに限られる。

無彩色には**わずかに温かみのある灰（ウォームグレー）**を用いる。純粋な灰より、紙や自然物に馴染む。コレクションの紙の質感とも連続する。

### 2.2 ライトテーマ

**ニュートラル（ウォームグレー）**

| トークン | 値 | 用途 |
|---|---|---|
| `--c-bg` | `#FAFAF9` | 画面の地 |
| `--c-surface` | `#FFFFFF` | カード・シートの面 |
| `--c-surface-sunken` | `#F5F5F4` | 入力欄、控えめな区画 |
| `--c-border` | `#E7E5E4` | 境界線 |
| `--c-border-strong` | `#D6D3D1` | 強調した境界線 |
| `--c-text-subtle` | `#6E6762` | 補助的な文字（日時、件数） |
| `--c-text-muted` | `#57534E` | 二次的な文字 |
| `--c-text` | `#292524` | 本文 |
| `--c-text-strong` | `#1C1917` | 見出し |

> **補助的な文字を「薄いグレー」にしない。** 日時や件数は装飾ではなく読む情報であり、本文と同じ 4.5:1 の基準を満たす必要がある。当初 `#A8A29E` を割り当てていたが実測 2.52:1 で不合格だったため、階調全体を1段ずつ濃くした（第9.1節）。

**アクセント（深緑）**

| トークン | 値 | 用途 |
|---|---|---|
| `--c-accent-bg` | `#EDF5F0` | 選択中の行、控えめな強調の背景 |
| `--c-accent-border` | `#B7D5C5` | 強調した枠線 |
| `--c-accent` | `#2D6A4F` | **主要ボタン、選択中のタブ、リンク** |
| `--c-accent-hover` | `#245740` | 押下・ホバー |
| `--c-accent-text` | `#1B4332` | 淡い背景の上に置く文字 |

**セマンティック**

| トークン | 値 | 用途 |
|---|---|---|
| `--c-danger` | `#A4161A` | 破壊的操作（脱退・削除・ブロック） |
| `--c-danger-bg` | `#FBEAEA` | その背景 |
| `--c-warning` | `#B45309` | 注意（有効期限が近い等） |
| `--c-info` | `#2D6A4F` | 情報。**アクセント色を流用する**（色を増やさない） |

### 2.3 ダークテーマ

端末のテーマ設定に追随する。深緑はそのままでは暗い地に沈むため、明度を上げた緑に差し替える。

| トークン | 値 |
|---|---|
| `--c-bg` | `#1C1917` |
| `--c-surface` | `#292524` |
| `--c-surface-sunken` | `#1C1917` |
| `--c-border` | `#44403C` |
| `--c-border-strong` | `#57534E` |
| `--c-text-subtle` | `#A8A29E` |
| `--c-text-muted` | `#D6D3D1` |
| `--c-text` | `#E7E5E4` |
| `--c-text-strong` | `#FAFAF9` |
| `--c-accent-bg` | `#1B3B2C` |
| `--c-accent-border` | `#2D6A4F` |
| `--c-accent` | `#52B788` |
| `--c-accent-hover` | `#74C69D` |
| `--c-danger` | `#F08C8C` |
| `--c-danger-bg` | `#3B1A1A` |
| `--c-warning` | `#E8A33D` |

**トークン名は両テーマで同一とする。** コンポーネントはテーマを意識せず、常に `--c-accent` のような役割名だけを参照する。

### 2.4 色の使用規則

| 規則 | 内容 |
|---|---|
| 深緑を装飾に使わない | アクセントは「押せる」「今ここ」「達成した」にのみ用いる。飾りで緑を置かない |
| 赤は取り消せない操作にのみ | 脱退・削除・ブロックなど、影響が戻せない操作に限る。エラー表示には用いるが、**未達成や未設定には用いない**（原則5） |
| 色だけで意味を伝えない | 認証バッジ、状態、エラーはいずれも形または文字を伴う（第9章） |
| グループごとの色分けをしない | タイムラインが色の見本市になる。グループの区別は名前とバッジで行う |

## 3. タイポグラフィ

### 3.1 書体

日本語主体のため、端末が持つ書体を用いる。Webフォントは読み込まない。**通知が生命線のアプリで、書体の読み込み待ちが初期表示を遅らせる事態を避ける。**

```
font-family:
  -apple-system, BlinkMacSystemFont,
  "Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", "Meiryo",
  system-ui, sans-serif;
```

数値（リアクション数、メンバー数、スタンプ数）には `font-variant-numeric: tabular-nums` を指定する。数が増減しても桁がずれない。

### 3.2 スケール

| トークン | サイズ / 行間 | 用途 |
|---|---|---|
| `--fs-caption` | 12px / 1.6 | 日時、補助ラベル |
| `--fs-small` | 13px / 1.7 | メタ情報、注記 |
| `--fs-body` | 15px / **1.8** | **本文（連絡・コメント）** |
| `--fs-subtitle` | 17px / 1.6 | 一覧項目の主題、グループ名 |
| `--fs-title` | 20px / 1.5 | 画面の見出し |
| `--fs-display` | 26px / 1.4 | コレクションの見出しなど、限られた場面 |

**本文の行間を1.8と広めに取る。** 日本語は英語より字面が詰まって見えるため、欧文の標準的な行間では読みづらい。連絡を確実に読んでもらうことが本アプリの目的である以上、ここは削らない。

### 3.3 字送りと太さ

| 項目 | 規則 |
|---|---|
| 太さ | 400（本文）と 700（見出し・強調）の2段階のみ。中間の太さは端末により再現されないことがある |
| 字送り | 日本語には指定しない（既定）。英数字の見出しのみ `-0.01em` |
| 行長 | 本文は最大 42文字程度で折り返す。それ以上は目が戻る位置を見失う |

## 4. スペーシングとレイアウト

### 4.1 スペーシングスケール

4px を基本単位とする。

| トークン | 値 | 主な用途 |
|---|---|---|
| `--sp-1` | 4px | 密接した要素の間 |
| `--sp-2` | 8px | アイコンと文字の間 |
| `--sp-3` | 12px | 関連する要素の間 |
| `--sp-4` | 16px | **既定の余白。画面の左右余白** |
| `--sp-6` | 24px | 区画の間 |
| `--sp-8` | 32px | 意味のまとまりの間 |
| `--sp-12` | 48px | 画面上下の大きな区切り |

**スケール外の値を使わない。** 「あと2pxだけ」を許すと、余白の一貫性が失われる。

### 4.2 レイアウト

| 項目 | 規則 |
|---|---|
| 画面左右の余白 | `--sp-4`（16px） |
| コンテンツ最大幅 | 640px（PC表示時は中央寄せ） |
| 一覧項目の最小高さ | 56px |
| タップ領域の最小 | **44×44px**。見た目が小さくても当たり判定を確保する |
| セーフエリア | `env(safe-area-inset-*)` を尊重する。タブバーは下部のセーフエリア分だけ内側に置く |

### 4.3 タイムラインの構造

実用の層の代表として、レイアウトの原則を示す。

```
┌────────────────────────────────┐
│                                │ ← --sp-6（区画の間）
│  すみだローバースカウト協議会 ✓  │   --fs-subtitle / 700
│  10月12日の集会について          │   --fs-body / 700
│                                │ ← --sp-3
│  今週土曜、いつもの公民館に9時    │   --fs-body / 400 / 行間1.8
│  集合です。持ち物は…             │
│                                │ ← --sp-4
│  ◯◯◯＋3人が参加            │   アバター重ね + --fs-small
│                                │ ← --sp-3
│  了解 4      参加したい 6        │   --fs-small / --c-text-muted
│                                │
├────────────────────────────────┤ ← --c-border（1px）
│                                │
│  たまがわローバー会 ✓            │
└────────────────────────────────┘
```

**区切りは線ではなく余白を主とする。** 線は最小限（1px、`--c-border`）に留め、項目のまとまりは余白で示す。カードを重ねて影を落とす表現は用いない。

## 5. 形状と奥行き

### 5.1 角丸

| トークン | 値 | 用途 |
|---|---|---|
| `--r-sm` | 6px | 入力欄、小さなバッジ |
| `--r-md` | 10px | ボタン、カード |
| `--r-lg` | 16px | シート、モーダル |
| `--r-full` | 9999px | ピル、アバター |

### 5.2 奥行き

**実用の層では影を使わない。** 面の違いは背景色（`--c-surface` と `--c-bg`）と境界線で示す。影を多用すると、ミニマルな印象が崩れ、ダークテーマでの再現も難しくなる。

影を使うのは次の3か所のみ。

| 対象 | 影 |
|---|---|
| ボトムシート・モーダル | `0 -2px 16px rgba(28,25,23,0.08)` |
| タブバー（スクロール時） | `0 -1px 0 var(--c-border)`（線に近い扱い） |
| **コレクションのスタンプ・カード** | 第7章で別途定義 |

## 6. コンポーネント

### 6.1 ボタン

| 種別 | 見た目 | 用途 |
|---|---|---|
| Primary | 深緑の塗り＋白文字 | 画面の主行動。**1画面に1つ** |
| Secondary | 境界線＋深緑の文字 | 副次的な行動 |
| Ghost | 背景なし＋`--c-text-muted` | 取り消し、一覧内の軽い操作 |
| Danger | 境界線＋`--c-danger` の文字 | 脱退・削除・ブロック |

| 項目 | 値 |
|---|---|
| 高さ | 44px（標準）／ 36px（小） |
| 左右余白 | `--sp-4` |
| 角丸 | `--r-md` |
| 文字 | `--fs-body` / 700 |
| 無効時 | 不透明度 0.4、操作を受け付けない |
| 処理中 | 文字を保ったまま左にスピナー。**幅を変えない**（押した位置がずれない） |

**Danger を塗りにしない。** 赤い塗りのボタンは押す前から威圧感を与える。境界線と文字色で十分に区別でき、かつ確認ダイアログで最終的に止められる。

### 6.2 認証バッジ

グループが認証済みであることを示す。**色以外の手がかりを必ず持たせる**（基本設計書 第13.4節）。

```
すみだローバースカウト協議会 ✓
                            ↑ 深緑の丸に白のチェック / 14×14px
```

| 項目 | 規則 |
|---|---|
| 形 | 円形の地に白いチェック |
| 色 | `--c-accent` |
| 配置 | グループ名の直後、`--sp-1` の間隔 |
| 代替テキスト | 「認証済みの公式組織」 |
| **未認証時** | **何も表示しない。**「未認証」のラベルは出さない（原則5） |

### 6.3 参加意向の表示

決定36の実装。連絡に「参加したい」を付けた人を、同じ連絡を受け取った人に見せる。

```
（●）（●）（●）＋3人が参加
 ↑ アバター24px、-8px 重ね、最大4人
```

| 項目 | 規則 |
|---|---|
| 表示 | アバターを最大4人まで重ね、以降は「＋N人」 |
| 0人のとき | **何も表示しない**（「まだ誰もいません」と書かない） |
| 自分が含まれる場合 | 自分のアバターを先頭に置く |
| タップ | 参加者の一覧を表示 |

**0人のときに空を明示しない。** 「まだ誰も参加していません」という表示は、最初の1人になることをためらわせる。

### 6.4 リアクション

| 項目 | 規則 |
|---|---|
| 種別 | 「了解」「参加したい」の2つ |
| 未反応 | `--c-text-muted` の文字＋件数 |
| 反応済み | `--c-accent-bg` の地＋`--c-accent` の文字 |
| 件数 | 0のときは数字を出さず、ラベルのみ |
| **「了解」の内訳** | **表示しない。**件数のみ（基本設計書 第7.3節） |

### 6.5 タブバー

5タブ。中央のスキャンのみ扱いを変える。

```
┌──────┬──────┬────────┬──────┬──────┐
│ ホーム │コレク │ ╭────╮ │ 通知  │ マイ  │
│      │ ション │ │ ◉ │ │  ●   │ ページ │
│      │      │ ╰────╯ │      │      │
└──────┴──────┴────────┴──────┴──────┘
                  ↑ 深緑の円 56px
```

| 項目 | 規則 |
|---|---|
| 高さ | 56px ＋ セーフエリア |
| 選択中 | アイコンと文字を `--c-accent` |
| 中央（スキャン） | 深緑の円（56px）に白のアイコン。**常に強調** |
| 未読 | 通知タブに 8px の点。件数は出さない |

**中央を常に強調する理由。** QRはスタンプ獲得・カード交換・グループ参加の共通入口であり（決定18）、活動の現場では数秒で到達する必要がある。選択状態にかかわらず、常に「ここを押せばよい」と分かる形にする。

### 6.6 入力

| 項目 | 規則 |
|---|---|
| 高さ | 44px（1行）／ 最小88px（複数行） |
| 地 | `--c-surface-sunken` |
| 枠 | なし（未フォーカス）／ `--c-accent` 1.5px（フォーカス時） |
| ラベル | 入力欄の上に配置。プレースホルダで代用しない |
| エラー | 枠を `--c-danger`、下に理由を `--fs-small` で示す |
| 文字数制限 | 上限に近づいたときのみ残数を表示する |

**プレースホルダをラベル代わりにしない。** 入力を始めると消えるため、何を書く欄だったか分からなくなる。

### 6.7 グループ名の重複判定

決定21の摩擦を緩和する要のUI（基本設計書 第7.2節 F-02）。

```
グループ名
┌──────────────────────────────┐
│ 夏キャンプ2027               │
└──────────────────────────────┘
  この名前は使われています

  こちらはいかがですか
  ┌────────────────────────┐
  │ 夏キャンプ2027（東京第1地区） │  ← タップで入力
  └────────────────────────┘
```

| 項目 | 規則 |
|---|---|
| 判定 | 入力停止から400ms後に照会する |
| 使用可 | 控えめなチェックのみ。祝わない |
| 使用不可 | **エラーとして赤くしない。** `--c-text-muted` で事実を述べ、すぐ下に代替案を出す |
| 代替案 | 1〜3件。タップで入力欄へ反映。**強制ではない** |

**重複を赤いエラーにしない。** これは利用者の間違いではなく、単に先に使われていたというだけである。作成の手軽さを損なわないため、事実の提示と提案にとどめる。

### 6.8 空状態

各画面に固有の空状態を用意する。

| 画面 | 表示 |
|---|---|
| タイムライン（未所属） | 「まだどのグループにも参加していません」＋グループを探すボタン |
| タイムライン（所属済み・連絡なし） | 「新しい連絡はまだありません」 |
| コレクション（スタンプ） | 空の枠を薄く並べ、「活動に参加するとここに集まります」 |
| コレクション（カード） | 「QRを読み取ると、出会った人のカードが集まります」＋スキャンへの導線 |

**コレクションの空状態では、空の枠を並べて見せる。** 何も置かないより、これから埋まる場所だと分かるほうが集める動機になる。

### 6.9 破壊的操作の確認

脱退・つながり解除・ブロック・削除に用いる。

| 項目 | 規則 |
|---|---|
| 形式 | ボトムシート |
| 見出し | 何が起きるかを一文で。「本当によろしいですか」と問わない |
| 本文 | **取り消せるかどうかを明示する** |
| ボタン | 実行（Danger）／ 取り消し（Ghost）。取り消しを左に置く |

例：

> **このグループから脱退します**
> 今後このグループの連絡は届きません。もう一度参加することはできます。
> 　[ 取り消し ]　[ 脱退する ]

**「もう一度参加できる」ことを書く。** 戻れると分かっていれば、利用者は操作をためらわない。逆に戻れない操作（グループの削除）では、はっきりそう書く。

## 7. コレクションの質感

**このアプリで唯一、装飾を許す領域である。**

### 7.1 地

| 項目 | 値 |
|---|---|
| 背景（ライト） | `#F7F3EC`（わずかに黄みのある紙色） |
| 背景（ダーク） | `#22201D` |
| テクスチャ | 極小のノイズを重ねる（不透明度 3% 以下）。画像は使わず CSS で生成する |

紙色は無彩色スケールから意図的に外す。**この領域だけ「別の場所」だと感じさせる**ためである。

### 7.2 スタンプ

```
   ╔═══════╗
   ║       ║   縁：1.5px のヘアライン（箔押し風）
   ║   ◉   ║   地：テンプレートで指定した色
   ║       ║   影：0 1px 2px rgba(0,0,0,0.10)
   ╚═══════╝
    夏キャンプ
    2027.08.14
```

| 項目 | 規則 |
|---|---|
| 形 | 円形／六角形／盾形からテンプレートで選択 |
| サイズ | 一覧で 88px、詳細で 200px |
| 縁 | `#C9A227`（箔）または `#8A8580`（銀）のヘアライン1.5px |
| 影 | `0 1px 2px rgba(0,0,0,0.10)` — 紙に貼られている程度 |
| 配置 | 3列グリッド、`--sp-4` の間隔 |
| 未獲得の枠 | 破線の枠のみ。中身は描かない |

### 7.3 プロフィールカード

| 項目 | 規則 |
|---|---|
| 縦横比 | 63:88（トレーディングカードの比率） |
| 角丸 | `--r-md` |
| 構成 | 上部に色帯 → アバター → 表示名 → 所属（表示する場合のみ）→ 自己紹介 |
| 縁 | 内側に 1px の白いハイライト。厚みを感じさせる |
| 影 | `0 2px 6px rgba(0,0,0,0.12)` |
| 一覧 | 2列グリッド |

### 7.4 やらないこと

| やらないこと | 理由 |
|---|---|
| 3D回転・傾き | 端末によって性能差が大きく、酔いを誘発する場合がある |
| 光沢の走るアニメーション | 一覧に多数並ぶと目が休まらない |
| 効果音・振動 | 活動の現場（屋外・会議中）で使うため |
| レアリティ表示 | スタンプは活動の記録であり、価値の序列をつけない |

**最後の項目は方針として重要である。** スタンプに「レア度」を持ち込むと、参加しやすい活動と参加しにくい活動に優劣が生まれる。すべての活動参加を等しく記録する。

## 8. モーション

| 項目 | 値 |
|---|---|
| 標準の長さ | 180ms |
| 短い変化（押下・切替） | 120ms |
| 画面遷移 | 240ms |
| イージング | `cubic-bezier(0.2, 0, 0, 1)`（ease-out 寄り） |

| 規則 | 内容 |
|---|---|
| 位置より不透明度 | 大きく動かさない。淡く現れる程度に留める |
| 一覧の項目を個別に animate しない | 順に現れる演出は、件数が多いと待たされる |
| **`prefers-reduced-motion` を尊重する** | 指定がある場合、遷移以外のアニメーションを無効化する |
| スタンプ獲得時のみ例外 | 獲得の瞬間だけ、スタンプが軽く弾む（400ms）。**このアプリで最も嬉しい瞬間**であり、ここには演出を置く |

## 10. 「開きたくなる」ための設計

基本設計のレビューで、「用がないのに開く理由が一つもない」という指摘があった。機能は揃っているが、通知が来たときにしか起動しない状態では、課題1（情報伝達）は解けても課題2（参加意欲）は解けない。

デザインで手当てできる範囲を、次の4点として定める。

| # | 仕掛け | 置き場所 | ねらい |
|---|---|---|---|
| 1 | **参加意向の顔ぶれ** | タイムライン（第6.3節） | 「誰が行くか」が見えることが、開く理由になる |
| 2 | **コレクションの未獲得枠** | コレクション（第7.2節） | 埋まっていない場所が見えると、埋めたくなる |
| 3 | **スタンプ獲得時の演出** | 獲得直後（第8章） | このアプリで最も嬉しい瞬間を、はっきり嬉しくする |
| 4 | **タブの控えめな新着表示** | コレクションタブ | 新しいスタンプ・カードがあるときだけ点を出す |

**これらはデザインで解ける部分にすぎない。** 「開く理由」の本質は、活動そのものが楽しいかどうかにある。アプリができるのは、その楽しさを記録し、次の参加につなげることまでである。過剰なゲーム化（ランキング、連続記録、通知による催促）は行わない。それは参加を義務に変え、課題2をかえって悪化させる。

## 11. 実装方針

### 11.1 トークン

**すべての値を CSS カスタムプロパティとして1か所に定義する。** コンポーネントは生の値を書かず、必ずトークンを参照する。

```css
:root {
  --c-accent: #2D6A4F;
  --sp-4: 16px;
  --fs-body: 15px;
  /* … */
}

@media (prefers-color-scheme: dark) {
  :root { --c-accent: #52B788; /* … */ }
}
```

ユーティリティCSS（Tailwind 等）の採用は任意とする。採用する場合も、**トークンを唯一の出所とし、設定ファイルからこれを参照する**。生の値をクラス名に直接書くことは禁じる。

### 11.2 コンポーネントの分類

| 層 | 内容 | 例 |
|---|---|---|
| プリミティブ | トークンを直接まとうもの | Button, Input, Badge, Avatar |
| パターン | プリミティブの組み合わせ | PostCard, GroupRow, StampTile, ConfirmSheet |
| 画面 | パターンの配置 | `06_screen_spec.md` で定義 |

**プリミティブは業務を知らない。** `Button` は「連絡を投稿する」を知らず、色と大きさと状態だけを知る。業務の語彙はパターン層から現れる。

### 11.3 ダークテーマ

`prefers-color-scheme` に追随する。アプリ内の手動切り替えは**設けない**。設定項目を増やさず、端末の設定を尊重する（原則3）。
